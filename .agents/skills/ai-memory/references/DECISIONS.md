# Architectural Decision Records (ADR) — ContentPilot 2.0

## ADR-001: Структура репозитория и приватный GitHub-репозиторий
- **Дата**: 2026-10-23
- **Статус**: Принято
- **Контекст**: Пользователь запросил разделить проект на две директории: `frontend` и `backend`, сохранить дизайн-кит и документацию, и выложить проект в приватный репозиторий GitHub.
- **Решение**: Репозиторий размещен в `https://github.com/ignatgft/ContentPilot` (private). Корневая структура соответствует разделу 3 ТЗ: `/frontend`, `/backend`, `/design-kit`, `/docs`, `docker-compose.yml`, `.env.example`, `README.md`.

## ADR-002: Планировщик без внешних брокеров очередей
- **Дата**: 2026-10-23
- **Статус**: Принято
- **Контекст**: Раздел 2 ТЗ строго фиксирует: «Spring @Scheduled и таблица задач в PostgreSQL. Redis и брокеры очередей не добавлять».
- **Решение**: Реализован `PublisherScheduler` со Spring `@Scheduled(fixedRate = 60000)`, который атомарно переводит посты в статус `PUBLISHING` и отправляет в Telegram Bot API.

## ADR-003: Дизайн-токены CSS и динамическая смена тем
- **Дата**: 2026-10-23
- **Статус**: Принято
- **Контекст**: Раздел 4 ТЗ требует строго следовать токенам `tokens.css`, использовать светлую тему по умолчанию и темную при `data-theme="dark"` на теге `<html>`, сохраняя выбор в `localStorage`.
- **Решение**: Создан `ThemeContext` на фронтенде с автоматическим считыванием системной темы (`prefers-color-scheme`) и `localStorage`. Переключатели вынесены в шапку и экран настроек.

## ADR-004: Отказоустойчивый Claude API генератор для хакатона
- **Дата**: 2026-10-23
- **Статус**: Принято
- **Контекст**: Во время демо хакатона внешний Claude API может быть недоступен из-за отсутствия ключа, блокировок или исчерпания квоты. Демо должно гарантированно проходить за 3 минуты.
- **Решение**: В `ClaudeGenerationService` реализован вызов Claude API (модель `claude-3-5-sonnet-20241022`) с автоматическим переходом на локальный контекстный генератор постов при отсутствии ключа или ошибке сети. Пост №3 генерируется с ценой 250₽ вместо 320₽ для демонстрации критерия приёмки блокировки `NEEDS_REVIEW`.

## ADR-005: Защита эндпоинта /error в Spring Security
- **Дата**: 2026-10-23
- **Статус**: Принято
- **Контекст**: В Spring Boot при возникновении любого HTTP 4xx/5xx запросы перенаправляются на внутренний URI `/error`. Если `/error` не разрешен в `SecurityConfig`, клиент получает ложный 403 Forbidden вместо информативного текста ошибки.
- **Решение**: `/error` явно добавлен в `.permitAll()` в цепочке фильтров `SecurityFilterChain`.

## ADR-006: Гибридная схема авторизации Web (Cookie) и Mobile (Bearer Header)
- **Дата**: 2026-10-23
- **Статус**: Принято
- **Контекст**: В веб-браузерах `HttpOnly` Cookie являются золотым стандартом для предотвращения XSS-атак при хранении Refresh токена. Однако на мобильных устройствах Flutter `HttpOnly` Cookie не поддерживаются прозрачно во всех версиях WebView и мобильных сетевых стеков.
- **Решение**: Реализован заголовок `X-Client: mobile`. При его наличии бэкенд возвращает `refreshToken` прямо в теле ответа `AuthResponseDto`. Flutter-приложение сохраняет его в аппаратный криптографический контейнер `flutter_secure_storage` (Android Keystore / iOS Keychain), а веб-клиент продолжает безопасно использовать `HttpOnly` куки.

## ADR-007: Мульти-паблишинг архитектура через единый интерфейс Publisher
- **Дата**: 2026-10-23
- **Статус**: Принято
- **Контекст**: Требуется поддержка 5 различных социальных сетей (Telegram, VK, YouTube Shorts, Instagram Graph API, TikTok) с кардинально разными моделями API, лимитами символов и статусами прохождения модерации/аудита платформы.
- **Решение**: Создан реестр `PublisherRegistry` и интерфейс `SocialPublisher`. Для платформ в стадии аудита (TikTok) введён промежуточный статус `READY_MANUAL`, а эндпоинт `GET /api/v1/channels/capabilities` отдаёт клиентам динамические ограничения площадок без хардкода на клиенте.

## ADR-008: Выбор Flutter + Riverpod для мобильного клиента
- **Дата**: 2026-10-23
- **Статус**: Принято
- **Контекст**: Необходим высокопроизводительный нативный клиент для Android и iOS с поддержкой офлайн-кэширования, строгой типизацией, реактивным состоянием и возможностью переиспользования единой бизнес-логики.
- **Решение**: Использован Flutter 3.47 с Dart 3.13 и библиотекой `flutter_riverpod` (StateNotifier/AsyncNotifier). Riverpod обеспечивает полную изоляцию бизнес-логики от UI, безопасное внедрение зависимостей и простое тестирование без бойлерплейта.

## ADR-009: Сетевой доступ и обход AP-изоляции через Cloudflare Tunnel
- **Дата**: 2026-10-23
- **Статус**: Принято
- **Контекст**: Локальный ПК подключен по Ethernet (`192.168.10.181`), а смартфоны — по Wi-Fi. На большинстве домашних и офисных роутеров включена изоляция клиентов (AP isolation), а брандмауэр Windows Defender по умолчанию блокирует входящие порты `3000` и `8080`.
- **Решение**: Развёрнут легковесный Cloudflare Quick Tunnel (`cloudflared`). Он создаёт зашифрованный QUIC/HTTP2 туннель от локального порта `3000` Nginx до глобального адреса `https://allows-thread-dedicated-screening.trycloudflare.com`, обеспечивая мгновенный защищённый доступ с любого смартфона по Wi-Fi и мобильным сетям (4G/LTE) без необходимости прав администратора Windows и проброса портов на роутере.

## ADR-010: Серверная валидация цен и предотвращение галлюцинаций LLM
- **Дата**: 2026-10-23
- **Статус**: Принято
- **Контекст**: Языковые модели могут случайно сгенерировать неверные цены, даты или скидки (например, указать 250₽ вместо утвержденных в меню 320₽).
- **Решение**: Вся сгенерированная кампания проходит детерминированный сервис валидации `VerificationService` перед сохранением. Несовпадающие факты маркируются статусом `NEEDS_REVIEW`, выводятся в специальный баннер на клиенте и требуют подтверждения или исправления в 1 клик.

## ADR-011: Nginx как единая точка входа (Reverse Proxy & APK Distribution)
- **Дата**: 2026-10-23
- **Статус**: Принято
- **Контекст**: Необходимо отдавать фронтенд, проксировать API-запросы на бэкенд и раздавать готовый релизный APK-файл приложения без необходимости поднимать отдельный файловый сервер.
- **Решение**: Контейнер `contentpilot-frontend` на базе Nginx настроен с правилами: SPA роутинг (`try_files $uri /index.html`), проксирование `/api/` на `backend:8080` с передачей оригинальных заголовков, и прямая отдача `/contentpilot.apk` как `application/octet-stream`.

## ADR-012: UI / UX Pro Max редизайн с нативными векторными ассетами
- **Дата**: 2026-10-23
- **Статус**: Принято
- **Контекст**: Стандартный интерфейс с Material Icons выглядел шаблонно и не раскрывал потенциал дизайн-кита ContentPilot.
- **Решение**: Реализован дизайн Pro Max: нативные цветные SVG-ассеты соцсетей (`PlatformIcon`), иконки дизайн-кита (`AppIcon`), глубокие градиенты, карточки со стеклянным эффектом `CpCard`, живые статус-бейджи `CpStatusBadge` и интерактивные недельные таймлайны в календаре.
