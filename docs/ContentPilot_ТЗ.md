# ContentPilot: ТЗ для ИИ-агента-разработчика

Этот документ даёт агенту всё нужное, чтобы собрать веб-сервис ContentPilot 2.0 для хакатона. Работай по порядку из раздела 10, после каждого этапа запускай проект и проверяй критерии.

## 1. Контекст

ContentPilot — ИИ-маркетолог на автопилоте для малого бизнеса. Пользователь описывает бизнес, выбирает бизнес-цель (например, продвинуть новый продукт), сервис строит кампанию, генерирует публикации, проверяет факты, публикует в Telegram по расписанию и показывает аналитику.

Цепочка: бизнес-цель → стратегия → генерация → проверка → публикация → измерение → рекомендации.

Первая ниша: кофейни. Язык интерфейса: русский, кыргызский добавить позже через файлы переводов.

## 2. Стек (зафиксирован)

- Фронтенд: React + Vite + TypeScript, Tailwind CSS, React Router, TanStack Query.
- Бэкенд: Java 21, Spring Boot 3 (Web, Data JPA, Security, Validation), Flyway, springdoc-openapi.
- База: PostgreSQL 16.
- Планировщик: Spring `@Scheduled` и таблица задач в PostgreSQL. Redis и брокеры очередей не добавлять.
- ИИ: Claude API через серверный REST-клиент.
- Запуск: Docker Compose (frontend, backend, postgres), одна команда `docker compose up`.

## 3. Структура репозитория

- `/frontend`: React-приложение.
- `/backend`: Spring Boot, пакеты `auth`, `brand`, `campaign`, `generation`, `verification`, `post`, `scheduler`, `publisher`, `analytics`.
- `/design-kit`: распакованный `contentpilot-kit.zip` (иконки, логотипы, аватарки, баннеры, токены).
- `/docs`: этот файл и описание API.
- `docker-compose.yml`, `.env.example`.

## 4. Дизайн-кит и темы

- Взять `design-kit/tokens/tokens.css` и подключить в корне фронтенда. Светлая тема по умолчанию, тёмная включается атрибутом `data-theme="dark"` на `<html>`.
- Переключатель темы в шапке и в настройках. Выбор хранить в `localStorage`, по умолчанию следовать системной теме.
- Шрифт Manrope (Google Fonts), веса 400, 500, 700, 800.
- Иконки: SVG из `design-kit/icons`, цвет через `currentColor`. Подключить как React-компоненты.
- Логотип: `logo/mark-*.svg` и `logo/wordmark-*.svg` по теме. Аватарки из `avatars/`, значки площадок из `platforms/`.
- Не использовать цвета вне токенов. Минимальная высота интерактивных элементов 44 px. Контраст текста не ниже WCAG AA.
- Статусы не передавать одним цветом: рядом всегда текст («Пройдено», «Требует проверки»).
- Значки площадок в ките временные (буквы). Для Google-входа использовать официальную кнопку Google Identity Services, а не свою иконку.

## 5. Регистрация и вход

Экран по макетам «Регистрация — светлая/тёмная».

- Поля: почта, пароль. Кнопка «Продолжить с Google». Ссылка «Уже есть аккаунт? Войти» (отдельный экран входа в том же стиле).
- Правила пароля: минимум 8 символов, буквы и цифры. Ошибки показывать под полем на русском.
- Пароли хранить только как хеш (BCrypt). Не логировать пароли и токены.
- Сессия: JWT access token (короткий срок) + refresh token в httpOnly cookie. Выход удаляет refresh token.
- Google: OAuth 2.0 / OpenID Connect, проверка ID-токена на бэкенде. Если почта уже есть, привязать Google к существующему аккаунту.
- Секреты (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `JWT_SECRET`, `CLAUDE_API_KEY`, `TELEGRAM_BOT_TOKEN`) только в переменных окружения. В репозиторий коммитить только `.env.example`.
- Подтверждение почты и сброс пароля: вторая очередь, не блокируют MVP.

## 6. Экраны

1. Регистрация и вход.
2. Онбординг бренда: описание, аудитория, меню и цены, график, адрес, примеры постов, логотип.
3. Выбор бизнес-цели и параметров (срок, аудитория).
4. Кампания: список публикаций, редактирование, перегенерация.
5. Проверка перед публикацией: статусы по фактам бренда, формату площадки и ценам. Заблокированный пост нельзя опубликовать до ручного подтверждения.
6. Календарь: перетаскивание по датам.
7. Подключение Telegram-канала.
8. Аналитика: показатели из подключённых площадок и рекомендации.
9. Настройки: режим автономности (ручной, полуавтомат, автопилот), тема, язык, кнопка «Остановить всё».

Макеты: https://claude.ai/artifact/LzX38UWvZmT6AXyEJRxtnU. Нарисованы: генератор, цель кампании, календарь, бренд, аналитика, регистрация (обе темы). Остальные экраны строить по тем же токенам и компонентам.

## 7. Данные (основное)

| Таблица | Поля |
| --- | --- |
| users | id, email, password\_hash (может быть пустым при входе через Google), google\_sub, created\_at |
| brands | id, user\_id, name, description, audience, tone, facts (JSON: меню, цены, график, адрес), autonomy\_mode |
| brand\_samples | id, brand\_id, text |
| campaigns | id, brand\_id, goal, period\_start, period\_end, status |
| posts | id, campaign\_id, platform, text, media\_url, status, scheduled\_at, published\_at, error |
| verification\_results | id, post\_id, check\_type, status, message |
| channels | id, brand\_id, platform, external\_id, encrypted\_token, status |
| publish\_log | id, post\_id, attempt, result, message, created\_at |
| post\_metrics | id, post\_id, views, reactions, clicks, collected\_at |

Статусы поста: `DRAFT`, `NEEDS_REVIEW`, `SCHEDULED`, `PUBLISHING`, `PUBLISHED`, `FAILED`, `PAUSED`.

## 8. Ключевая логика

- **Генерация:** по профилю бренда, примерам и цели запрашивать у Claude кампанию в формате JSON (темы, тексты по площадкам, сценарии коротких видео). Ответ валидировать, при ошибке разбора повторить запрос.
- **Проверка:** сверять цены и условия в тексте с `brands.facts`, искать стоп-слова и запрещённые обещания, проверять длину под площадку и повторы. Несовпадение даёт `NEEDS_REVIEW`.
- **Публикация:** планировщик раз в минуту берёт посты `SCHEDULED` со временем в прошлом, атомарно переводит в `PUBLISHING`, вызывает Telegram Bot API, пишет результат в `publish_log`. До 3 попыток, затем `FAILED`. Двойная публикация недопустима.
- **Аналитика:** показывать только реально собранные данные. Рекомендации строить на этих данных, статистику не придумывать. Если данных нет, так и написать.
- **Стоп:** кнопка «Остановить всё» переводит все запланированные посты бренда в `PAUSED`.

## 9. Ограничения и безопасность

- Доступ к данным только владельцу бренда (проверка `user_id` в каждом запросе).
- Токены каналов шифровать в базе.
- Ограничить частоту запросов на регистрацию, вход и генерацию.
- Живая публикация только в Telegram. Для остальных площадок режим «готово к публикации» со скачиванием материалов. Неофициальные обходы API не использовать.
- Загрузка файлов: проверять тип и размер.

## 10. Порядок работ и критерии приёмки

| Этап | Что сделать | Критерий |
| --- | --- | --- |
| 1. Каркас | Репозиторий, Docker Compose, Flyway-схема, токены и темы, переключатель темы | `docker compose up` поднимает всё, тема переключается |
| 2. Авторизация | Регистрация, вход, Google, выход | Можно войти почтой и через Google, чужие данные недоступны |
| 3. Бренд | Онбординг и профиль | Профиль сохраняется и редактируется |
| 4. Кампании | Выбор цели, генерация, редактирование | Цель даёт кампанию с постами по площадкам |
| 5. Проверка | Сверка цен и фактов | Пост с неверной ценой получает `NEEDS_REVIEW` и не публикуется |
| 6. Публикация | Календарь, планировщик, Telegram | Пост уходит в канал в заданное время, статус `PUBLISHED` |
| 7. Аналитика и режимы | Метрики, рекомендации, режимы автономности, «Остановить всё» | Все режимы работают, стоп останавливает публикации |
| 8. Финиш | Обе темы на всех экранах, тестовые данные для демо | Демо проходит за 3 минуты без ручных правок в базе |

Готовность к демо: из пустого аккаунта за 3 минуты создать бренд (кофейня), поставить цель «продвинуть сезонный латте», увидеть заблокированный пост с неверной ценой, исправить, утвердить кампанию и увидеть живой пост в Telegram-канале.
