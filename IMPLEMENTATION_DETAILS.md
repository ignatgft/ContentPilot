> **Документ создан в рамках стандарта AI-Memory.**  
> В файле подробно зафиксировано: **что реализовано**, **какие страницы существуют**, **как они устроены** и **почему выбраны именно такие архитектурные решения**.

## 1. Обзор системы и цель проекта

**ContentPilot** — омниканальная ИИ-платформа для автоматизации контент-маркетинга малого бизнеса (пилотная ниша: спешелти кофейни, локальный ритейл, сфера услуг).

### Проблема малого бизнеса
Владелец малого бизнеса не имеет времени и бюджета на найм отдельного SMM-агентства или копирайтера, но обязан вести социальные сети для привлечения клиентов. Обычные LLM (ChatGPT/Claude) генерируют оторванные от реальности тексты, придумывают несуществующие цены и скидки (галлюцинации), а также не умеют публиковать контент в социальные сети.

### Решение ContentPilot
1. **Память бренда (Brand Memory)**: бизнес фиксирует меню, цены, адрес, часы работы, ЦА и тон общения.
2. **ИИ-генератор с контекстом**: генерация контент-плана или отдельных постов под конкретную бизнес-цель на базе Claude 3.5 Sonnet.
3. **Строгий серверный фактчекинг**: каждый пост сверяется с базой цен. При несовпадении публикация блокируется (`NEEDS_REVIEW`).
4. **Омниканальный паблишинг**: адаптация и отправка в **Telegram**, **ВКонтакте**, **YouTube Shorts**, **Instagram**, **TikTok**.
5. **Интерактивный календарь и Автопилот**: автоматическое планирование на 7 дней вперед или режим ручного одобрения (Копилот).
6. **Кнопка экстренной остановки (Kill Switch)**: мгновенная пауза всех публикаций во всех соцсетях при форс-мажоре.

## 2. Что реализовано (Архитектурный стек)

### 2.1. Бэкенд (Java 21 / Spring Boot 3.3.4)
- **Безопасность**: Spring Security, Stateless JWT (HMAC-SHA384), BCrypt хеширование.
- **База данных**: PostgreSQL 16 Alpine, Spring Data JPA, Hibernate ORM.
- **Миграции**: Flyway (`V1__init_schema.sql`).
- **Фоновый планировщик**: Spring `@Scheduled(fixedRate = 60000)` с атомарной выборкой задач из PostgreSQL.
- **Интеграция с ИИ**: Клиент Claude API (Anthropic REST API, модель `claude-3-5-sonnet-20241022`) с отказоустойчивым локальным fallback-генератором.
- **Мульти-паблишинг**: Модульная архитектура адаптеров социальных сетей (`TelegramPublisher`, `VkPublisher`, `YouTubePublisher`, `InstagramPublisher`, `TikTokPublisher`).
- **Специфика мобильного клиента**: Поддержка заголовка `X-Client: mobile`, возвращающего `refreshToken` в теле ответа для безопасного хранения в защищенном хранилище смартфона.

### 2.2. Веб-фронтенд (React 19 / TypeScript / Vite / Tailwind CSS)
- **Стек**: React 19, TypeScript, Vite, Tailwind CSS v4, Lucide React, TanStack Query v5, React Router v7.
- **Дизайн-система**: Токены `tokens.css` и `tokens.json`, полная поддержка светлой и тёмной темы, адаптивная верстка.
- **Интеграция**: Все запросы идут через относительный путь `/api/v1/*`.

### 2.3. Мобильное приложение (Flutter 3.47 / Dart 3.13 / Android)
- **Стек**: Flutter 3.47, Dart 3.13, `flutter_riverpod` 2.6, `dio` 5.4, `flutter_secure_storage` 9.2, `flutter_svg` 2.0, `intl`.
- **UI / UX Pro Max**: Градиенты, стеклянные карточки `CpCard`, живые бейджи `CpStatusBadge`, градиентные кнопки `CpGradientButton`, цветные векторные SVG-ассеты соцсетей (`PlatformIcon`).
- **Безопасность сети**: `network_security_config.xml` с разрешением локального HTTP-трафика для отладки.

### 2.4. Инфраструктура и сеть
- **Docker Compose**: 3 контейнера (`contentpilot-postgres`, `contentpilot-backend`, `contentpilot-frontend`).
- **Nginx Reverse Proxy**: Единая точка входа на порту 3000: раздача SPA, проксирование `/api/` на бэкенд, прямая раздача `contentpilot.apk`.
- **Cloudflare Tunnel (QUIC / HTTP2)**: Глобальный защищенный доступ без необходимости белого IP и проброса портов на роутере: `https://allows-thread-dedicated-screening.trycloudflare.com`.

## 4. Как это реализовано (Техническое устройство)

### 4.1. Двухконтурная схема авторизации (Web + Mobile)
```
[Web Browser]  ──(credentials)──> POST /api/v1/auth/login ──> Access Token (JSON) + Refresh Token (HttpOnly Cookie)
[Mobile App]   ──(X-Client: mobile)──> POST /api/v1/auth/login ──> Access Token + Refresh Token (Оба в JSON теле)
                     │
                     ▼
          Flutter Secure Storage (Android Keystore / iOS Keychain)
```
- Веб-версия защищена от XSS за счёт хранения Refresh токена в `HttpOnly` cookie.
- Мобильное приложение отправляет заголовок `X-Client: mobile` и безопасно сохраняет refresh токен в аппаратном криптографическом хранилище `flutter_secure_storage`.
- В `ApiClient` на базе `Dio` настроен перехватчик `InterceptorsWrapper`: при получении HTTP 401 клиент автоматически вызывает `POST /api/v1/auth/refresh`, обновляет access token и прозрачно повторяет исходный запрос.

### 4.2. Механизм генерации и фактчекинга контента
```
[Цель / Промпт]
       │
       ▼
[ClaudeGenerationService] ──> Запрос к Claude 3.5 Sonnet (или контекстный fallback)
       │
       ▼
[VerificationService] ──> Поиск упоминаний цен и сопоставление с facts['menu']
       ├── Если цена совпадает (320₽) ──> Статус SCHEDULED (готов к публикации)
       └── Если цена не совпадает (250₽) ──> Статус NEEDS_REVIEW (блокировка публикации)
```

### 4.3. Автономный планировщик без очередей сообщений
По разделу 2 ТЗ запрещено использовать Redis, RabbitMQ и Kafka. Планировщик `PublisherScheduler` работает по таймеру Spring `@Scheduled(fixedRate = 60000)`:
1. Выполняет атомарный SQL-запрос `SELECT ... WHERE status = 'SCHEDULED' AND scheduled_at <= NOW() FOR UPDATE SKIP LOCKED`.
2. Переводит выбранные посты в статус `PUBLISHING` (защита от двойной отправки в кластере).
3. Передаёт пост в соответствующий адаптер из `PublisherRegistry`.
4. При успехе выставляет `PUBLISHED` и фиксирует лог в `publish_log`. При ошибке — до 3 повторов с фиксацией в `last_error`.

### 4.4. Доставка трафика с телефона через Cloudflare Tunnel
- На компьютере разработчика запущен контейнер Docker с Nginx на порту 3000.
- Nginx перенаправляет запросы `/api/*` в контейнер `contentpilot-backend:8080`.
- Утилита `cloudflared` открывает исходящее зашифрованное соединение с сетью Cloudflare Edge:
  `cloudflared tunnel --url http://127.0.0.1:3000`
- Внешний адрес `https://allows-thread-dedicated-screening.trycloudflare.com`:
  - Отдаёт Web SPA при открытии в браузере телефона.
  - Принимает REST API запросы от мобильного приложения Flutter.
  - Раздаёт готовый бинарный файл `contentpilot.apk` для установки на смартфон.

## 5. Почему это реализовано именно так (Архитектурные обоснования / ADR)

| Архитектурное решение | Альтернатива | Почему выбрано текущее решение |
|---|---|---|
| **Flutter для мобильного приложения (ADR-008)** | React Native, PWA, нативный Kotlin/Swift | Flutter компилируется в прямой машинный код AOT, обеспечивает стабильные 60/120 FPS, имеет лучшую кроссплатформенную отрисовку на Canvas/Impeller и даёт единую кодовую базу для Android и iOS. |
| **State Management: Riverpod (ADR-008)** | Bloc, Provider, GetX | Riverpod не зависит от `BuildContext`, предотвращает утечки памяти при фоновых запросах, строго типизирован во время компиляции и легко тестируется. |
| **Аппаратное `flutter_secure_storage` (ADR-006)** | SharedPreferences | `SharedPreferences` хранит данные в открытом XML-файле, уязвимом на рутованных устройствах. `flutter_secure_storage` шифрует токены через Android Keystore и iOS Keychain. |
| **Spring `@Scheduled` + PostgreSQL (ADR-002)** | Redis, Celery, RabbitMQ | Прямое требование ТЗ (раздел 2). Избавляет от необходимости поддерживать и мониторить дополнительную инфраструктуру очередей; база PostgreSQL гарантирует ACID-транзакционность и целостность расписания. |
| **Серверный фактчекинг цен (ADR-010)** | Валидация на клиенте | Клиентскую валидацию легко обойти или отключить. Серверный фактчекинг гарантирует, что ни один пост с галлюцинацией LLM не попадет в реальные соцсети даже при сбое клиентского приложения. |
| **Cloudflare Quick Tunnel (ADR-009)** | Открытие портов на роутере (Port Forwarding), ngrok | Не требует прав администратора на рабочей станции, не требует статического «белого» IP от провайдера, обходит изоляцию Wi-Fi/Ethernet (AP Isolation) и защищен SSL-сертификатом Cloudflare по протоколу HTTP/2 / QUIC. |
| **Nginx как единый дистрибьютор APK (ADR-011)** | Загрузка на Google Drive / сторонние файлообменники | Файл APK отдается напрямую тем же веб-сервером проекта (`/contentpilot.apk`), гарантируя мгновенную загрузку на мобильные устройства на максимальной скорости без сторонней рекламы и капч. |
| **Дизайн-система Pro Max с SVG (ADR-012)** | Стандартные растровые PNG или иконки шрифтов | Векторные SVG-файлы (`PlatformIcon`, `AppIcon`) не теряют четкости на экранах смартфонов с высокой плотностью пикселей (Retina / AMOLED), весят в десятки раз меньше растра и идеально соответствуют фирменному дизайн-киту проекта. |

## 6. Проверенный сценарий Демо (3 минуты)

Для презентации жюри или инвесторам предусмотрен непрерывный сценарий, работающий прямо из коробки:

1. **Мгновенный вход**: Нажать кнопку **«Вход в Демо-аккаунт (1 клик)»** на экране авторизации (`demo@contentpilot.app` / `Password123!`).
2. **Память бренда**: Вкладка «Бренд» → нажать **«Заполнить кофейню для демо (3 мин)»** → подставляются данные спешелти кофейни «Зёрна и Истории», меню и цены (Латте 320₽, Капучино 250₽). Нажать «Сохранить».
3. **Генерация контента**: Вкладка «Создать» → выбрать пресет *«☕ Сезонный латте Тыква-Пряности»* → нажать **«Сгенерировать публикации»**.
4. **Проверка фактчекинга**: Пост для Telegram генерируется с ценой 250₽ вместо 320₽. Система автоматически окрашивает карточку в янтарный цвет, выставляет статус **`NEEDS_REVIEW`** и блокирует кнопку «В эфир».
5. **Исправление и публикация**: Нажать **«Одобрить»** (или исправить цену) → статус обновляется на **`SCHEDULED`**, после чего нажать **«В эфир сейчас»** → статус мгновенно переходит в **`PUBLISHED`**, пост отправляется в Telegram-канал.
6. **Экстренная остановка (Kill Switch)**: Нажать иконку щита в шапке или в настройках → подтвердить **«Остановить всё»** → все запланированные публикации получают статус **`PAUSED`**.
